**Goal:** A second annotator, running alongside `r0b_lvra`, that publishes the multiclass champion's scores (plus challenger/retired slots) and public lightcurve features, backed by a `features.db` SQLite store.

**Architecture:** A new `lvra_feature_maker → lvra_predict → lvra_annotator` chain reads the same Kafka JSON files as r0b. Features are a port of H's `CleanDataAndMakeFeatures` notebook, computed per alert from `diaSourcesList`. Rows go into `features.db` (`features`, `model_scores`). Progress is tracked in new `lvra` columns of `log.db`.

**Tech Stack:** Python, pandas 2.3.3, numpy 2.3.5, scikit-learn 1.8.0 (`HistGradientBoostingClassifier`), joblib, sqlite3, `lasair` client, bash + cron + flock.

**Spec:** `docs/superpowers/specs/2026-10-19-lvra-v2-prod-design.md` (read the **Amendment 2026-10-20** at the end; it overrides the earlier sections).

## Global Constraints

- r0b chain, `provenance`, `threshold_flags_provenance` and `kafka_consumer.py` are not modified.
- `classification` = `f"{p_extragal:.6f}"`, ≤ 80 chars. `version` ≤ 80. `classdict` JSON text < 4096 chars.
- `classdict` floats rounded to 6 significant figures. Model slots `champion`/`challenger`/`retired`, with an empty slot as `null` and `gal` left out.
- Public threshold names in `classdict` use r0b's names (`n_gtXX`, `brighterXX`, `firstXX`, XX ∈ 18–22).
- One `L.annotate` per object. No `annotate_list`.
- `features`: `diaSourceId` PRIMARY KEY, `INSERT OR IGNORE`. `features.db` runs in WAL mode with `PRAGMA foreign_keys = ON`, as a separate file from `log.db`.
- Status codes are the same as r0b: 1, -1, 21, 99 (plus 31 for missing features, as in `utils/predict.py`).
- `band` reaches the model as `pd.Categorical(categories=["u","g","r","i","z","y"])`.
- The prod env must pass `check_pckg_versions()` (sklearn 1.8.0).
- Plain SQL only, nothing SQLite-specific in table definitions except the `INSERT OR IGNORE` verb, so MariaDB migration is a copy.
- Branch `claude/lvra-v2-prod` off `claude/lvra-v2-prod-design`. Commit trailers: `Oversight-Mode: collab`, `Reviewed by: Heloise`.

## Review Focus

1. **NaN in `classdict`.** `json.dumps` writes `NaN`, which is not valid JSON, so Lasair may reject it. NaN/None features must serialise as `null`. Numpy ints and bools must become Python types. → test in Task 7.
2. **Old stems flood the new chain.** After the `ALTER TABLE`, every historical stem must stay untouched by `lvra_*`, while every new stem the consumer writes (the consumer does not name `lvra`) must get picked up. → migration design and test in Task 8.
3. **Re-running a stem duplicates scores.** A stem with status -1 is retried. `model_scores` must not get a second row per (alert, role, version). → test in Task 3.
4. **Duplicate `diaObjectId` in one JSON** (two alerts in one poll, see `features.py` dev notes). This should give two `features` rows keyed by `diaSourceId`, and the annotator sends the latest one only. → tests in Tasks 2 and 7.
5. **An unsorted `diaSourcesList`.** The trigger must be the latest by `midpointMjdTai`, not the last list item, or every "latest" feature is wrong. → test in Task 2.
